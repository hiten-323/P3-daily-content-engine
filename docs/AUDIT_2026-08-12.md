## Verified findings

### 1. Constitution and policy

- Architecture remains frozen under ADR-001.
- Brand/editorial quality is now aligned at **8.0** across the constitutional default and founder policy.
- Founder policy was bumped from `1.0` to `1.1` on 2026-08-12 to remove the previous 6.5-vs-8.0 ambiguity.
- `editorial_engine.get_current_pass_score()` remains the runtime policy accessor.

### 2. Scheduling

The live schedule is:

| Slot | IST | UTC cron | Responsibility |
|---|---:|---:|---|
| Generate | 06:00 | `30 0 * * *` | Research, generation, gates, creative, non-IG distribution |
| Morning | 10:00 | `30 4 * * *` | Instagram carousel + Facebook mirror |
| Evening | 22:00 | `30 16 * * *` | Instagram reel + Facebook mirror |

`content_generator/core/slot_registry.py` is the source of truth. README and ARCHITECTURE were corrected to match it. A new operational-alignment test prevents the 08:00/20:00 documentation drift from returning.

### 3. Learning state

The `output/learning/` tree is present and tracked in the repository, including:

- `published_posts.json`
- `performance_log.json`
- `account_metrics.json`
- `follower_snapshots.json`
- policy and diagnostic logs

The important operational observation is that `performance_log.json` is currently empty while many tracked Instagram posts remain `insights_recorded: false`. Therefore the learning loop must be treated as **cold-start / unmeasured**, not as a healthy learned system.

This is not safely fixable by inventing metrics. The correct next action is to validate the Meta token/account permissions and allow genuine observations to accumulate.

### 4. Instagram token monitoring

A dedicated GitHub Actions workflow now checks the Instagram Graph API daily at **05:45 IST**, before the 06:00 generate run. HTTP 401/403 responses trigger `ALERT_WEBHOOK_URL` and fail the health workflow.

The check uses Graph API `v24.0`, matching `config/api_versions.py`.

### 5. Tests / regression protection

The engineering hardening workflow now includes an operational-alignment regression suite covering:

- 8.0 editorial threshold consistency
- 06:00 / 10:00 / 22:00 schedule
- README schedule accuracy
- ARCHITECTURE schedule and threshold accuracy
- tracked learning-state files

Existing measurement-window, account-funnel, evidence, psychology, publishing, fallback, and config-drift checks remain in the suite.

## Remaining priorities

### P1 — Measurement

1. Confirm `INSTAGRAM_ACCESS_TOKEN` has the required Meta permissions and the Instagram account is eligible for insights.
2. Confirm the new token-health workflow is green.
3. Accumulate real 24h/72h/7d observations before enabling stronger learning decisions.

### P2 — Attribution

The architecture intentionally uses honest day-level attribution where Instagram cannot provide per-post purchase links. A UTM/link-in-bio layer remains the highest-value future improvement for true post → session → order attribution.

### P3 — ADR-002

Keep later scroller-psychology phases gated on actual measurement volume. Do not convert the current cold-start state into learned doctrine.

### P4 — Execution

Founder-produced hero-video throughput remains the major human execution dependency.

## Conclusion

**Keep the architecture frozen.** The correct next move is not another architectural rewrite. It is to get trustworthy Instagram observations flowing, verify the token-health alert path, and let the existing learning/evidence safeguards operate on real data.
