# ADR-001: Architecture Frozen

**Status:** Accepted
**Date:** 2026-07-03

## Decision

The architecture of the Purity Beans Growth Operating System is frozen as
described in ARCHITECTURE.md:

- Three-slot daily loop on GitHub Actions (generate 06:00 / morning 08:00 /
  evening 20:00 IST)
- State persisted as JSON in the repo (`output/learning/`), committed each run
- Free-tier LLM cascade for generation; deterministic heuristics for selection
  (hooks, hashtags)
- Closed learning loop: Instagram insights + Shopify revenue → viral memory →
  next day's prompts
- Dual-track content: growth (non-branded) + brand (jar + buy CTA), governed
  by stage-aware ratios

## Context

Between June and July 2026 the system evolved from a daily content scheduler
into a growth operating system through ~15 major feature commits. Each addition
was validated with tests before merge. Continuing to add architectural surface
now has worse expected value than letting the learning loop accumulate data.

## Consequences

- **Implementation continues; architecture does not.** Parameter tuning,
  prompt-bank additions, bug fixes, and new rotation content are normal
  commits. New modules, new external dependencies, new pipeline stages, or
  changes to the state model require a new ADR.
- The next architectural candidates (already identified, deliberately
  deferred — see UNKNOWNS.md and past reviews) are: click-level attribution
  via bio link, email capture loop, comment/DM automation via Meta webhooks,
  and compliant competitor intelligence. Each needs its own ADR with a
  cost/benefit case built on accumulated performance data.

## Rationale (Prefer evidence over elegance)

The binding constraint on growth is now **data volume** (posts published ×
metrics recorded), not system capability. Every week of stable operation makes
the learning loop smarter; every architectural change risks the consistency
that compounds. Freeze, operate, measure, then evolve through ADRs.
